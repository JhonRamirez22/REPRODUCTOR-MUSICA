# Decisiones

- Se crea el proyecto en `outputs/reproductor-estructuras-datos` porque el workspace de esta tarea es el directorio de salida autorizado; el directorio indicado contiene el brief, no código inicial.
- La interfaz parte del fallback de tokens de la sección 9.4 de `AGENTS.md`: `uipro` y su generador `search.py` no están instalados en el entorno; no añado esa herramienta como dependencia de producción.
- La dirección de diseño conserva el dark-first cálido, un acento coral, tipografía de sistema y jerarquía por espacio indicados en `AGENTS.md`; no se carga tipografía remota para evitar una dependencia de red de la interfaz.
- `jsdom` queda como dependencia de desarrollo junto a Testing Library porque los componentes React requieren un DOM para verificar sus interacciones; no forma parte de la imagen de producción.
- `TEST_DATABASE_URL` queda comentada en `.env.example` para que `npm run check` no intente conectarse ni borrar datos hasta que se active el perfil temporal de pruebas de PostgreSQL.
- `VITE_API_PROXY_TARGET` permite apuntar Vite a otro puerto de Fastify si el 3000 ya está ocupado en desarrollo.
- A petición del usuario, la búsqueda e inserción de pistas usa `ytmusicapi`, solicitada mediante el repositorio compartido; es una biblioteca no oficial y la consulta pública de catálogo no necesita API key ni autenticación.
- El servidor valida que el `videoId` elegido aparezca para el texto de búsqueda y guarda solo metadatos y referencia; el navegador reproduce el resultado en el YouTube IFrame Player API visible y no descarga ni extrae audio.
- La app instala `ytmusicapi` en un entorno Python aislado dentro de Docker. En desarrollo se fija `ytmusicapi==1.12.3` en `server/requirements.txt`; la decisión de añadir una dependencia Python externa se justifica por la petición explícita del usuario de emplear esa biblioteca.
- `ytmusicapi` corre dentro del contenedor Fastify de ECS, donde están instalados Python y sus dependencias. `YTMUSIC_API_URL` y `YTMUSIC_API_TOKEN` quedan como opción para separar el catálogo en otro runtime cuando se configure explícitamente.
- Vercel entrega solo `web/dist` como sitio estático y reescribe `/api/*` hacia el origen HTTPS de ECS Express Mode. Esto evita iniciar Fastify como función Vercel —la causa de la pantalla `FUNCTION_INVOCATION_FAILED`— y conserva las cookies en el origen público del sitio.
- `JAMENDO_CLIENT_ID` y la ruta de streaming antigua se conservan únicamente para compatibilidad de reproducción con registros creados por la versión anterior; el buscador ya no usa Jamendo.
- YouTube prohíbe la reproducción en segundo plano: el iframe se pausa al ocultarse la página y Media Session solo se registra para fuentes de audio directo, de modo que sus controles no reanuden YouTube en segundo plano.
- El usuario eligió Aurora PostgreSQL y AWS. Para conectar el contenedor sin contraseñas persistentes se usa autenticación IAM de Aurora, tokens temporales del SDK oficial `@aws-sdk/rds-signer` y TLS con el bundle global de CA de RDS más Amazon Root CA 1 (el gateway Express presenta certificados de Amazon Trust Services); `DATABASE_URL` se mantiene para desarrollo local y otros proveedores.
- El backend se despliega como contenedor ECS Express Mode en `us-east-1`, con endpoint HTTPS administrado, y el frontend permanece estático en Vercel con una reescritura del mismo origen para `/api/*`. Aurora PostgreSQL Express usa su Internet Access Gateway con autenticación IAM y TLS. Las tareas usan subredes públicas para alcanzar Aurora y YouTube Music; el grupo de seguridad limita el tráfico entrante al balanceador. La cuenta AWS Free rechazó siete días de retención; el clúster usa el día permitido por el plan, protección contra borrado y la base de aplicación creada después del clúster.
- App Runner no es el destino de contenedor porque AWS cerró el servicio a nuevos clientes el 31 de marzo de 2026. CodeBuild construirá la imagen desde la rama pública `main` del repositorio y la publicará en ECR con una etiqueta derivada del commit.
- Los archivos locales se añaden al final de la playlist seleccionada dentro del estado de sesión del navegador y se reproducen con `HTMLAudioElement` mediante una URL `blob:` temporal; así no se sube audio ni se cambia el esquema persistente de playlists. Hay que volver a elegirlos tras recargar. El CSP permite `blob:` únicamente en `media-src` para habilitar ese flujo.
- Las cuentas usan correo normalizado, hash scrypt con sal aleatoria y tokens de sesión aleatorios guardados como SHA-256; se elige criptografía nativa de Node para evitar otra dependencia y exponer secretos en la base. La sesión dura 30 días y usa cookie firmada, HttpOnly, SameSite=Lax y Secure en producción.
- El ID de la cuenta conserva el ID anónimo actual al registrarse para adoptar las playlists ya creadas sin una migración destructiva. Después se rota la cookie anónima para que cerrar sesión no vuelva a mostrar las playlists de la cuenta.
- No se configura un proveedor de correo en esta entrega: no hay verificación ni recuperación automática de contraseña. La interfaz, README y aviso de privacidad informan esa limitación; borrar una cuenta queda bajo gestión de la instancia.
